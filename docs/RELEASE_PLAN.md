# THE LAST TURN — Release Plan

**Status:** Planning baseline v1.0  
**This is a readiness framework, not a delivery-date promise.**

## 1. Release stages

1. **Internal prototype:** one mission can start, progress, complete/fail and reset in Studio.
2. **Internal alpha:** core loop, one location, at least one functional entity and Ghost Mode integrated.
3. **Closed playtest:** unfamiliar players can understand the mission and play without developer coaching.
4. **Public soft launch:** limited but complete experience, monitoring, feedback and patch process.
5. **Wider public launch:** expand discovery and content cadence after quality and retention signals justify it.

## 2. Release gates

### Gate A — Project foundation
- HUB and MISSION Places exist and Rojo mappings are reproducible.
- Repository setup, naming, lint/test workflow and documentation are clear.
- Server/client boundaries and remote security conventions are in place.

### Gate B — First playable mission
- Party can launch a reserved mission server.
- ASYLUM graybox is navigable.
- Mission objectives and team resource contribution work.
- Mission can complete and fail.
- Return-to-HUB flow works.
- Solo and multiplayer lifecycle tested in Studio.

### Gate C — Core experience
- Investigation/evidence and equipment work.
- At least one entity has a complete behavior/counterplay loop.
- Contact, hunt and final ritual are playable.
- Death and Ghost Mode work without bypassing objectives.
- Multiple runs are meaningfully different and solvable.

### Gate D — Content and progression
- Three MVP entity archetypes are implemented and balanced.
- Target equipment and event variety are present.
- Basic progression and rewards are reliable.
- Mission variations do not create softlocks.

### Gate E — Release candidate
- PC and mobile controls/UI validated.
- Performance and memory checked on representative devices.
- Server-authority and exploit-sensitive interactions reviewed.
- Data persistence and reward idempotency tested where applicable.
- Closed playtests show objective comprehension, fair failure and replay intent.
- Critical blockers resolved.

### Gate F — Public release
- Experience title, icon, thumbnails, description and onboarding ready.
- Basic analytics and feedback/support process ready.
- Monetization, if included, is optional, cosmetic and compliant with current Roblox rules.
- Patch/rollback and update communication process established.

## 3. Progress reporting

Track separately:
- Implementation status.
- Automated validation.
- Roblox Studio validation.
- Playtest/product validation.
- Known risks and blockers.

Do not calculate launch progress from merged PR count or lines of code. A phase is complete only when its exit criteria have evidence. Keep estimates directional until playtest evidence exists.

## 4. Post-launch candidates

Additional maps, entities, seasonal content, expanded cosmetics, advanced social systems and LiveOps are not automatic launch blockers. Prioritize them using actual player feedback, retention and development capacity.

A Roblox ranking is an ambition, not an acceptance criterion or guaranteed outcome.
